# v0.2.1 — 2026-04-08

(D) 2026-04-08

### Added

- **`app/reminders/page.tsx`**: Authenticated `/reminders` page that loads reminders via `fetchReminders` (pagination, optional search, and read/unread/all filter), marks items read with `markReminderReadApi`, and keeps an unread count in `localStorage` under `reminderUnreadCount` while dispatching a `reminder-count-updated` window event so the shell can show a live badge.
- **`app/component/header.tsx`**: Reminders navigation (desktop and mobile) to `/reminders` with an `AlarmClock` icon, a badge driven by the stored unread count (capped for display), and listeners for `reminder-count-updated` plus `storage` so the count updates when the reminders page changes or another tab writes the same key. Document title map includes `Reminders | Userbase` for `/reminders`.

### Changed

- **`app/component/header.tsx`**: Reminder badge count stays in sync with the reminders page through the shared `reminderUnreadCount` / `reminder-count-updated` mechanism instead of requiring a full navigation refresh.

### Fixed

- Not applicable for this scoped release (only reminders page and header integration described above).

### Security (if applicable)

- Reminder unread counts are stored in the browser (`localStorage`). On shared devices, clearing site data or using a private window limits exposure; the count is not a secret but reflects user-specific UI state.

### Internal

- Contract between `app/reminders/page.tsx` and `app/component/header.tsx`: `reminderUnreadCount` in `localStorage` and the `CustomEvent("reminder-count-updated", { detail: { count } })` event keep the header badge aligned with the loaded reminder list after fetch and after marking items read.
