# v0.2.8 - 2026-04-16

(D) 2026-04-16

### Added
- **`app/signup/page.tsx`:** Password strength checks now include at least one digit (`hasNumber`), aligned with the backend rule that passwords must include a number and a special character.
- **`app/signup/page.tsx`:** `isRoleMismatchApiMessage()` so certain role-related API errors surface as the same friendly copy used on login.

### Changed
- **`app/login/page.tsx`:** Added `isEmailNotFoundApiMessage()` and an expanded `isRoleMismatchApiMessage()` for classifying API error text. Failed login shows a single inline error: unreachable-server messages pass through; role-style API errors map to “Could not find the user with this role.”; other API failures map to “Email or password is incorrect.” Redundant client-side password rule checks before calling `login()` were removed so the API remains authoritative for password validation.
- **`app/signup/page.tsx`:** Live password hint and submit validation use one combined requirement message when length, symbol, or number rules are not met; removed the old commented-out phone validation block; signup API errors use the role-mismatch mapping above when applicable.
