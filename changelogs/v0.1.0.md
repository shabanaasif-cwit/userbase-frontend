# v0.1.0 — 2026-03-19

(D) 2026-03-19

### Added

- Admin page(s) at `/admin/notifications` to create, update, and delete notifications.
- UI to target notifications by “all”, “by role”, or “specific users” (mock data / localStorage until backend API exists).
- Notification list in admin panel with edit/delete actions.
- Notifications store (`app/lib/notifications-store.ts`) for frontend-only persistence.
- Notifications display on the dashboard and as an alert banner.
- Header with notification list/dropdown.
- User notifications page at `/notifications`; mark as read in the UI (backend call ready when API exists).
- Auth: `ManagedUser` type, `getManagedUsers()`, `setUserStatus()`, `updateUserRole()`, `USER_STATUS_KEY`; login blocks deactivated users.
- Edit user (role and account status) and Deactivate/Activate actions; state in `localStorage`.
- Admin dashboard cards linking to `/admin/users` and `/admin/notifications`.
- Next.js optimizations: ISR on home, about, terms, privacy, gallery; server components with small client boundaries (WelcomeCTA, ContactForm); PageShell for content pages; metadata for SEO.
- Reusable `PageShell` component (variant light/dark, maxWidth narrow/default/wide).
- Global CSS for native `select`/`option` so dropdown options are visible.

### Changed

- Updated UI components for the notification section for better usability.
- Improved notification management interface for a more user-friendly approach.
- Notifications are interactive; users can open detailed views via modals.
- Admin Notifications create module: fixed height with scroll so the list does not expand as it grows.
- Integrated SSR, SSG, and ISR optimizations where applicable on Next.js pages.

### Fixed

- “Mark as read” now updates the unread badge count immediately after marking a notification.
- Notifications now display correctly on the dashboard.
- Dropdown options in the notification UI are visible without hover.
- Code refactored for clarity and maintainability.
