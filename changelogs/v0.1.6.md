# v0.1.6 - 2026-04-04

(D) 2026-04-04

### Added

- Support for admin-only and user-only notification targets in the admin notification workflow and API mapping.
- User ID handling for specific-user notifications so admins can target stored users using backend identifiers instead of email addresses.
- Search input and read-status filtering on the reminders page for easier browsing of reminder history.
- Pagination controls on the reminders page so users can move through reminder results page by page.

### Changed

- Admin notification management now offers `Admin`, `User`, `All`, and `Specific users` targeting options instead of role-based targeting.
- Notification payload mapping now accepts `targetUsers` responses from the API and keeps `targetUserIds` aligned for frontend usage.
- Managed user loading now extracts users from more backend response shapes and preserves each user record's `id`, `email`, and display name.
- Dashboard, header, profile, and notifications views now consistently operate on unread notification collections when showing quick notification lists and counters.
- Reminder fetching now supports backend query parameters for `page`, `limit`, `search`, and `read`.
- The reminders page summary now reflects paginated reminder totals instead of only the currently rendered local list length.

### Fixed

- Opening a notification now updates the active notification state as read immediately across notification surfaces.
- "Mark all read" actions now only submit unread notification IDs, preventing stale read items from remaining in unread-only views.
- Dashboard notification cards now mark auto-dismissed notifications as read in the backend after the timeout completes.
- Admin specific-user selection now toggles against user IDs correctly and surfaces a dedicated error when managed users fail to load.
- Marking a single reminder as read now updates the unread count on the current page immediately.
- Reminder empty states now respond correctly when search or read filters produce no matching results.

### Security (if applicable)

- No security-specific changes in this release.

### Internal

- Refined notification target typing in `app/lib/notifications-api.ts` by removing legacy role-target handling and aligning request/response helpers with the current backend contract.
- Added shared user-list extraction logic in `app/lib/auth-context.tsx` to normalize paginated and nested user API responses.
- Added reminder pagination parameter and metadata types in `app/lib/notifications-api.ts`.
- Added reminder pagination metadata parsing so the frontend can consume common backend paging response shapes.
