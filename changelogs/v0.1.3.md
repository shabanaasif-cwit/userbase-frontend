# v0.1.3 — 2026-04-01

(D) 2026-04-01

### Added

- Backend API integration layer: `app/lib/api-config.ts` (`API_BASE`, `authHeaders`, shared JSON helpers).
- `app/lib/notifications-api.ts`: list/create/update/delete notifications, mark read (`PATCH .../read`), send remind (`POST .../remind`), optional reminders list/read helpers; maps UI `message` ↔ API `body` for MongoDB-backed validation.
- Auth context exposes `accessToken` and restores session with `GET /api/auth/me` (no auth data in `localStorage`); profile updates via `PATCH /api/users/me`; logout calls `POST /api/auth/logout`.
- Admin user management uses `fetchUsersFromAPI`, `updateUserRoleAPI`, and `updateUserStatusAPI` against the Express API.
- Contact form submits with `POST /api/contact` instead of persisting to `localStorage`.

### Changed

- Notifications UI (header, dashboard, profile, user notifications page, admin notifications) loads and mutates data through the API with Bearer + `credentials` where applicable.
- `app/lib/notifications-store.ts` now re-exports types/helpers only (no browser storage for notifications).

### Fixed

- Admin notifications page: restored missing `useAuth()` / `accessToken` and `apiError` state so the list loader no longer throws at runtime.

### Security (if applicable)

- Session and user/notification data are intended to live on the server/DB; access token is kept in memory after login (refresh cookie flow depends on backend CORS/cookie settings).

### Internal

- Removed `localStorage` usage for auth session, registered users, admin emails, user status, and notification/read maps in favor of the backend and MongoDB.
