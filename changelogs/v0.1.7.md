# v0.1.7 - 2026-04-06

(D) 2026-04-06

### Added

- Admin notifications page for listing, creating, editing, deleting notifications, optional targeted delivery, and sending reminders against the notifications API.
- Admin users page for searching, filtering, paginating, editing role and account status, and quick activate/deactivate actions via the users API.
- Server redirect from `/admin/userRole` to `/admin/users` so legacy or bookmarked URLs resolve to the current user management screen.

### Changed

- Account status updates now attempt `PATCH /api/users/{id}` with `{ status }` first so the user record can be updated in line with typical REST partial updates; if that route is missing or disallowed, the client falls back to `PATCH .../deactivate` and `PATCH .../toggle-account` as before.
- User list mapping now derives `active` vs `deactivated` from common API shapes (`status`, `accountStatus`, `isActive`, `active`, `deactivated`, `isDeactivated`) so the admin table reflects backend and database fields more reliably after refetch.
- Profile display name handling prefers stored name fields and uses safer email-local fallbacks without treating dots as name separators, consistent with stricter signup and login email rules.
- Native `<select>` elements on dark admin surfaces use an explicit dark color scheme and scoped styling so the chosen option label remains readable on Windows and Chromium-based browsers.

### Fixed

- Admin user row action controls (edit, activate/deactivate) now receive clicks reliably by avoiding pointer-event conflicts between ghost buttons and icon SVGs.
- Admin user table row keys use a stable identifier (`id` or `email`) to reduce duplicate-key warnings and odd reconciliation when the API omits an `id`.
- User identifiers from the API are normalized (including Mongo-style `{ $oid }` objects) so PATCH paths use a consistent `userId` segment.

### Security (if applicable)

- No security-specific changes in this release.

### Internal

- Extended `app/lib/auth-context.tsx` with `deriveUserStatus`, tightened `normalizeUserId`, and updated `fetchUsersFromAPI` / `updateUserStatusAPI` behavior to align with backend user list and status endpoints.
- Added `select[data-native-dark]` and related rules in `app/globals.css` so admin filter selects stay legible without affecting light-theme selects globally.
